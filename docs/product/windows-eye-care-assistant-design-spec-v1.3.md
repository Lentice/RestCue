## 0. 變更記錄

### 0.1 v1.0 → v1.1（既有修正，保留）

本次 Review 修正了以下邏輯問題，未變動任何產品原則（Section 3.1）：

| 編號 | 問題 | 修正方式 |
|---|---|---|
| R-01 | 「離席判定」（預設 2 分鐘）與當時的「20 秒視為被動休息」互相矛盾。 | v1.1 先拆為兩個門檻；v1.3 再由 R-13 修正語義：20 秒只代表 `PassivePauseDetected`，不得視為完成休息或重設需求。 |
| R-02 | 狀態機缺少 `Paused → Working`、`FocusMode → Working`、`Idle → Working` 回復轉移，`Disabled` 狀態未被使用。 | 補齊所有回復轉移，並定義 `Disabled` 的進出條件。詳見 FR-003。 |
| R-03 | 「邊緣提示顯示時間」（預設 30 秒）到期後沒有定義行為，導致「不理會提醒」與「主動忽略」被混為一談，統計失真。 | 新增 `AutoDismissed` 結果與對應事件，與 `Ignored` 分開記錄。詳見 FR-003、FR-007、FR-010、9.2。 |
| R-04 | CPU < 0.5% 的效能目標沒有落地建議，工程實作容易超標。 | 在 NFR-001 補充建議輪詢頻率與實作方式。 |
| R-05 | 前景程式名稱記錄預設開啟，與其他欄位「預設不蒐集」的隱私立場不一致。 | 改為預設關閉、使用者需主動開啟。詳見 NFR-003。 |
| R-06 | `usage_events` 缺少查詢索引，統計功能會頻繁依時間區間查詢。 | 補上建議索引。詳見 9.2。 |
| R-07 | FR-009 情境規則切換自訂間隔時，現有累積工作時間該延續或歸零未定義。 | 明訂切換規則時的計時器行為。詳見 FR-009。 |

### 0.2 v1.1 → v1.2（本次修正：四方辯論收斂結果）

本次修正的來源，是針對「應該做的功能有哪些、UI/UX 該如何規劃」這個題目所做的多輪辯證，最終在多個方案間收斂出的共識與明確分歧點。修正原則：**只把已收斂的共識落地為需求，未收斂的分歧一律列入 Review Backlog，不在本版 MVP 搶先下注。**

| 編號 | 問題 | 修正方式 |
|---|---|---|
| R-08 | 提醒與狀態變化目前只分「彈窗／完全靜默」兩種呈現層級，缺少「周邊視覺、不打斷中央注意力」的中間層，導致使用者無法從沉默判斷「系統是否正常運作」。 | 新增**休息債務分級模型**（5.5）與**系統列微狀態**規則，把 Idle 進出、Focus Mode 結束、債務等級變化等原本「只寫日誌」的狀態轉移，改為透過系統列圖示的漸進式視覺變化呈現，不新增任何彈窗或音效。詳見 5.5、FR-004a、FR-010。 |
| R-09 | Break Guide 允許「靜音倒數模式」，倒數數字本身會把眼神留在螢幕上，形成「點了開始休息、卻仍盯著螢幕」的假休息。 | 移除所有形式的數字倒數呈現，Break Guide 一律採用去數字化的節奏型音效或極簡無數字進度光暈。新增可選的 Windows Spatial Audio（空間音效）引導模式。詳見 5.4、FR-006。 |
| R-10 | 「休息需求」「提醒時機」「呈現強度」目前隱含地混在同一套邏輯裡（例如「20 秒無輸入」同時被當作觸發條件與完成休息的證據），容易在後續擴充時產生邏輯矛盾（例如「因為現在不適合提醒,所以當作不需要休息」）。 | 明訂三者為三個獨立變數,禁止互相取代。詳見 5.5.1。 |
| R-11 | 是否應在 MVP 導入「深度工作／專注狀態」的自動偵測（例如依輸入節奏、滑鼠移動模式判斷是否延後提醒），在多輪討論後仍是未有共識的根本分歧：一方主張值得用有限規則換取「絕不打斷深度專注」，另一方主張這已構成行為模式輪廓建構，且沒有實測資料支撐閾值，不該在 MVP 階段下注。 | **明確排除於 MVP 之外**，理由不是技術做不到，而是在沒有 Dogfooding 資料前，任何一方的判斷都只是未經驗證的賭注。與 Windows Focus Assist 整合並列，一併留待 Dogfooding 之後、有實測資料時再評估。詳見 4.2、16。 |
| R-12 | 使用者無法用低成本方式確認「系統目前記錄了我什麼」，只能深入設定頁尋找。監控感的疑慮不會反映在 AutoDismissed 或忽略率等既有統計裡，卻同樣會導致停用。 | 新增**資料透明檢視**功能，系統列選單需在兩次點擊內可達,顯示目前實際蒐集中的資料類型與統計筆數。詳見 FR-012。 |

以下開放問題留待 Dogfooding 後進入 Review Backlog，本次不擴大 Scope：
- 是否整合 Windows 內建 Focus Assist（勿擾模式）狀態，作為情境規則的訊號來源之一。
- 是否引入任何形式的「深度工作／專注狀態」自動偵測（見 R-11；必須先證明現有規則的誤打斷問題與訊號可靠性）。
- 環境光／智慧燈具連動（見 4.2）。
- Windows Spatial Audio 是否具有可驗證的額外價值。


### 0.3 v1.2 → v1.3（本次修正：邏輯一致性與實證邊界）

本次修正不擴大 MVP 的產品野心，而是把最終辯論結論落實為更嚴謹的版本契約。核心原則是：**系統可以觀察沒有輸入，但不能把「沒有輸入」冒充為已完成遠眺；休息需求、提醒時機與呈現強度仍須分離；未經驗證的感官或專注推測不得成為 P0 依賴。**

| 編號 | 問題 | 修正方式 |
|---|---|---|
| R-13 | v1.2 將「20 秒無輸入」直接記為 `PassivePauseDetected` 並清除休息債務，但沒有輸入不代表使用者已離開螢幕或完成遠眺，與「系統不能假裝使用者已休息」的最終原則衝突。 | 將短暫無輸入改名為 **被動停頓（Passive Pause）**，事件改為 `PassivePauseDetected`。它可隱藏過期浮窗並暫緩呈現，但**不得記為完成休息、不得清除休息債務**。只有完整完成 Break Guide 或達到離席門檻進入 `Idle` 才能重設休息需求。詳見 3.3、5.2、FR-002、FR-003、FR-004、10.2。 |
| R-14 | v1.2 對 Pause 與 Focus Mode 的時間行為不一致：部分段落表示兩者都持續累積，10.1 又將 Pause 排除於有效工作時間之外。 | 明確區分：**Pause 停止有效工作時間與休息債務累積；Focus Mode 持續累積，但抑制主動提醒**。詳見 5.6、FR-008、10.1、C-002。 |
| R-15 | v1.2 同時描述「進入 `PendingReminder` 後開始累積債務」及「20／35／45／60 分鐘為債務等級」，容易把門檻解讀成到期後再加 20 分鐘。 | 定義唯一時間軸：休息需求時鐘自「上一次可信重設事件」起算；工作提醒間隔是 Level 1 門檻，35／45／60 分鐘皆是**自上次可信重設起的總有效工作時間**。詳見 5.5。 |
| R-16 | 最大等待時間到期後的行為與休息債務呈現等級互相衝突，可能導致 Level 1 就顯示浮窗。 | 最大等待只讓 Timing 進入「可提醒」狀態，不授予更高呈現權限；最終呈現仍由 `min(債務建議強度, 情境上限, 使用者通道設定)` 決定。詳見 5.1、5.5.3、FR-004、FR-004a。 |
| R-17 | Windows Spatial Audio 尚無實測證據證明比一般提示音更低干擾，卻在 v1.2 被列為 P0 Break Guide 模式與核心技術依賴。 | MVP 僅承諾一般節奏提示音、語音與無數字視覺替代。Spatial Audio 移至 **Optional Experiment / Review Backlog**，不得阻塞 MVP 發布，也不得成為 P0 驗收條件。詳見 4.2、FR-006、8.1、16、D-004。 |
| R-18 | v1.2 的「忽略／AutoDismissed 後重新計算下一週期」容易被誤解為休息需求歸零，與債務持續累積矛盾。 | 拆成兩個時鐘：**休息需求時鐘不重設**；僅設定下一次「提醒嘗試冷卻時間」。新增 Reminder Retry Cooldown，預設沿用工作提醒間隔，但不得晚於下一債務等級門檻。詳見 3.3、5.5.4、FR-007。 |
| R-19 | 系統列微狀態若只靠色調變化，不符合「不只用顏色表示狀態」的無障礙要求。 | 債務等級須同時透過可辨識的靜態形狀／徽記或 Tooltip 文字呈現；不得用動畫、閃爍或紅點搶注意力。詳見 FR-004a、NFR-005、D-001。 |

本版仍不解決、必須交由 Dogfooding 驗證的問題：
- 5 秒無輸入是否足以代表「適合提醒」，尤其在閱讀程式碼、觀察 Log 或架構思考情境。
- 明確離席門檻（預設 2 分鐘）是否足以作為可信的休息需求重設事件。
- 固定聲音與系統列微狀態長期使用後是否產生習慣化。
- 是否需要 Focus Assist 等既有 OS 訊號；不得直接跳到自製輸入行為模型。

## 2. 產品摘要

### 2.1 一句話定位
一個常駐 Windows 背景、能判斷使用者是否持續工作，並在自然停頓點提供不搶焦點、不遮蔽內容、可延後的護眼提醒工具。

### 2.2 使用者問題
長時間使用電腦時，使用者容易：
- 忘記依照 20-20-20 原則遠眺。
- 因專注而長時間不休息或減少眨眼。
- 對固定時間、突然跳出的提醒感到干擾。
- 在會議、簡報、全螢幕或高專注工作時不希望被打斷。
- 安裝提醒工具後，因提醒過於煩人而關閉軟體。
- **（v1.2 新增）對背景常駐軟體持續記錄自己的操作行為感到不安，即使資料只留在本機。**

### 2.3 產品目標
MVP 要驗證：
1. 非阻擋式提醒是否能長期保持啟用。
2. 智慧等待自然停頓是否比固定時間直接跳出更不干擾。
3. 使用者是否會實際執行 20 秒遠眺。
4. 哪些工作情境最容易忽略或延後提醒。
5. **（v1.2 新增）休息債務分級呈現，是否能在不使用行為推測的前提下，同時兼顧「不錯過休息」與「不打斷專注」。**

## 3. 需求分層

### 3.1 產品原則

以下原則為高穩定層，MVP 內不得違反：

1. 不得封鎖、停用或攔截鍵盤與滑鼠。
2. 不得使用全螢幕遮罩阻止使用者工作。
3. 不得顯示必須處理後才能繼續工作的 Modal Dialog。
4. 提醒不得搶走目前應用程式的輸入焦點。
5. 使用者必須能忽略、延後或關閉提醒。
6. 所有行為資料預設只儲存在本機。
7. 不記錄鍵盤輸入內容、剪貼簿內容、畫面內容或網站內容。
8. 不把產品描述為醫療診斷或治療工具。
9. **（v1.2 新增）不得對使用者的輸入節奏、滑鼠移動模式或操作序列進行連續性行為建模，用以推測專注或工作狀態。系統只能量測「多久沒有輸入」這類單純的時間性指標。**

> **原則 9 的說明**：這條原則直接對應 R-11。它劃出的界線不是「不能用任何行為訊號」，而是「只能用時間性訊號（idle duration），不能用模式性訊號（輸入頻率變化、滑鼠移動特徵）」。前者是 FR-002 從 v1.0 就存在的機制，後者則等同於對使用者建立行為輪廓，即使資料不落地儲存，持續在背景分析的行為本身就是本產品要避免的監控感來源。

### 3.2 MVP 版本承諾

MVP v1.3 必須交付：
- 系統列常駐程式。
- 有效工作時間偵測。
- 閒置（Idle）與被動停頓偵測（兩個獨立機制，見 3.3）。
- 20-20-20 計時狀態機。
- 等待自然輸入停頓後再提醒。
- 不搶焦點的螢幕邊緣提醒。
- 開始休息、延後、本次忽略三種操作，以及提醒逾時未回應的自動結束。
- 20 秒無畫面依賴、去數字化的休息引導（**v1.2 修正**：明確禁止數字倒數）。
- 全螢幕情境自動降級提醒。
- 暫停與專注模式。
- **（v1.3 延續）休息債務分級模型與對應的系統列微狀態呈現。**
- **（v1.3 延續）資料透明檢視（系統列可達）。**
- 每日基本統計。
- 本機設定與資料儲存。
- 開機自動啟動選項。

### 3.3 可調參數

以下參數必須配置化，不得硬編碼在 UI 邏輯中：

| 參數 | 預設值 | 可調範圍 | 備註 |
|---|---:|---:|---|
| 工作提醒間隔 | 20 分鐘 | 10–60 分鐘 | 亦為休息需求 Level 1 門檻 |
| 自然停頓判定 | 5 秒 | 2–30 秒 | 只判斷提醒時機，不代表已休息 |
| 最大等待提醒時間 | 3 分鐘 | 0–10 分鐘 | 到期後僅讓 Timing 變為可提醒，不提升呈現權限 |
| 遠眺時間 | 20 秒 | 10–60 秒 | 完整完成才記為 `BreakCompleted` |
| 延後時間 | 5 分鐘 | 1–30 分鐘 | 只延後提醒嘗試，不清除休息需求 |
| **離席判定（Idle Threshold）** | 2 分鐘 | 1–10 分鐘 | 進入 `Idle`、停止累積，並視為可信重設事件 |
| **被動停頓判定（Passive Pause Threshold）** | 20 秒 | 10–120 秒 | 偵測短暫無輸入；可隱藏過期提醒，但不得記為完成休息。必須 < 離席判定 |
| 邊緣提示顯示時間 | 30 秒 | 5–120 秒 | 超過後記為 `AutoDismissed` |
| **提醒重試冷卻時間** | 20 分鐘 | 1–60 分鐘 | 忽略／AutoDismissed 後的下次嘗試時間；不得晚於下一債務等級門檻 |
| 提示透明度 | 70% | 20–100% | |
| 每日摘要時間 | 關閉 | 不提供 | v1.3 移除此參數；統計只能主動開啟 |
| **休息債務等級門檻** | 20 / 35 / 45 / 60 分鐘 | 可個別調整 | 皆為自上次可信重設事件起算的總有效工作時間 |
| **休息引導模式** | 節奏提示音 | 提示音／語音／無數字視覺 | Spatial Audio 不屬於 MVP 必交付 |

> **v1.3 時間語義**：被動停頓與離席是不同事件。20 秒沒有輸入，只能證明「暫時沒有鍵鼠操作」，不能證明使用者已遠眺，因此不清除休息需求。達到離席門檻後，系統才可保守視為使用者已明確離開工作狀態並重設需求。兩個門檻必須滿足 `PassivePauseThreshold < IdleThreshold`。

## 4. MVP 範圍

### 4.1 In Scope

- Windows 10 / 11 桌面應用程式。
- 單一使用者、本機模式。
- 鍵盤與滑鼠活動「時間戳記」偵測（僅量測最後輸入時間，不分析輸入模式）。
- 前景程式與全螢幕狀態偵測。
- 系統列 UI，含休息債務等級的漸進式微狀態呈現。
- 螢幕邊緣非啟用式提示視窗。
- 提示音、語音或無數字視覺引導。
- SQLite 本機紀錄。
- 基本統計頁面。
- 每個前景程式的靜音規則。
- 資料透明檢視（系統列可達，顯示目前實際蒐集的資料類型）。

### 4.2 Out of Scope

以下功能不得納入 MVP，除非重新開啟 Scope Review：

- 攝影機眨眼辨識。
- 臉部、眼球或姿勢追蹤。
- 智慧手錶、手環或藍牙裝置整合。
- 雲端帳號與跨裝置同步。
- 遊戲化積分、成就與社群排行。
- AI 健康分析。
- 自動修改螢幕亮度、色溫或 Windows 設定。
- 環境光／智慧燈具連動（例如 Philips Hue、Windows Dynamic Lighting）——即使技術上零成本可行，MVP 階段目標使用族群的硬體滲透率過低，資源應集中在核心提醒與呈現機制上，列入 Future Backlog。
- 醫療建議、疾病診斷或視力評估。
- 企業集中管理後台。
- macOS、Linux 或行動版。
- Windows Focus Assist（勿擾模式）整合（列入 Dogfooding 後 Review Backlog）。
- Windows Spatial Audio 正式產品功能；只允許以不阻塞發布的 Optional Experiment 評估。
- **（v1.2 新增）任何形式的「深度工作／專注狀態」自動偵測，包括但不限於輸入頻率分析、滑鼠移動模式分析、個人行為基線建模。理由見 R-11 與原則 9。列入 Dogfooding 後 Review Backlog，與 Focus Assist 整合一併評估。**
- **（v1.2 新增）任何需要使用者「回顧」的主動彈出式摘要或每日總結通知；統計頁只能是使用者主動開啟才可見的資訊，不得有紅點或未讀提示。**

## 5. 核心使用流程

### 5.1 正常提醒流程

1. 程式在系統列常駐。
2. 使用者開始操作鍵盤或滑鼠，系統累積有效工作時間與休息需求時鐘。
3. 自上一次可信重設事件起達工作提醒間隔（預設 20 分鐘）後，休息債務進入 Level 1，狀態轉為 `PendingReminder`。
4. 系統等待連續無輸入達自然停頓判定（預設 5 秒）。
5. Timing 符合時，系統依 `PresentationIntensityPolicy` 決定是否只更新系統列，或顯示邊緣提醒。
6. 若最大等待時間（預設 3 分鐘）到期，Timing 視為可提醒；但不得因此跳過債務等級或情境上限。
7. 使用者可選擇：
   - 開始完整 Break Guide。
   - 延後。
   - 本次忽略。
   - 不回應，於顯示時間到期後記為 `AutoDismissed`。
8. 只有 `BreakCompleted` 或進入 `Idle` 會清除休息需求。延後、忽略、AutoDismissed、短暫無輸入與提前取消 Break Guide 均不清除。
9. 忽略或 AutoDismissed 後只啟動提醒重試冷卻，不重設休息需求時鐘。

### 5.2 離席與被動停頓流程

1. 使用者停止操作，系統持續計算 `IdleDuration`。
2. 若達被動停頓判定（預設 20 秒）但尚未達離席判定：
   - 記錄 `PassivePauseDetected`。
   - 若邊緣提醒仍可見，將其安靜淡出，避免使用者不在操作時留下過期浮窗。
   - 不記為完成休息、不清除休息需求、不重設連續工作時間。
   - 使用者恢復操作後，若需求仍到期，回到 `PendingReminder`，等待下一個自然停頓；不得在恢復輸入的瞬間彈出。
3. 若未操作持續達離席判定（預設 2 分鐘）：
   - 進入 `Idle`，停止累積有效工作時間。
   - 記錄 `IdleStarted`。
   - 視為可信的離席重設事件，清除休息需求與尚未完成的提醒嘗試。
4. 使用者恢復操作後：
   - 記錄 `IdleEnded`。
   - 進入新的 `Working` 週期。
   - 不恢復離席前的可見提醒。

### 5.3 全螢幕流程

1. 系統偵測前景視窗為全螢幕。
2. 休息需求與有效工作時間照常累積。
3. 不顯示邊緣浮窗；預設只允許靜態系統列狀態。
4. 輕提示音只有在使用者明確允許「全螢幕可播放聲音」時才可使用，預設關閉。
5. 離開全螢幕後，若需求仍到期，回到 `PendingReminder` 並等待自然停頓。
6. 只可產生一次後續提醒，不得按累積週期數連續補發。
7. 不得主動退出、最小化或切換全螢幕程式。

### 5.4 休息引導流程（v1.3：去數字化、完成語義明確化）

開始休息後：
- 不得顯示數字倒數。
- MVP 必須提供：
  - 節奏提示音模式：開始、中段、完成提示。
  - 簡短語音模式。
  - 無數字進度光暈：供靜音或聽覺不便情境使用，可完全關閉。
- Windows Spatial Audio 不屬於 MVP 必交付；只能以獨立實驗功能存在，預設關閉，失敗不得影響基本流程。
- 預設 20 秒引導內容：
  - 開始：看向約 6 公尺外。
  - 中段：慢慢眨眼並放鬆肩膀。
  - 完成：播放完成提示。
- 使用者可隨時取消，但提前結束一律記為 `BreakCancelled`，不得記為完成，也不得清除休息需求。
- 只有完整達到設定的遠眺時間，才記錄 `BreakCompleted` 並清除休息需求。
- 可使用滑鼠點擊或專用全域快捷鍵取消。不得把「任意滑鼠大範圍移動」作為完成或取消條件，避免正常操作誤觸。
- 不得模糊、降黑、遮罩畫面或阻止其他操作。

### 5.5 休息需求、提醒時機與呈現強度模型

#### 5.5.1 三個獨立變數

- **休息需求（Need）**：自上一次可信重設事件起累積的有效工作時間。
- **提醒時機（Timing）**：現在是否適合嘗試提醒，由自然停頓、最大等待、鎖定、全螢幕、Pause、Focus Mode 與情境規則決定。
- **呈現強度（Intensity）**：允許使用哪一種通道，由債務等級、情境上限與使用者通道設定共同決定。

三者禁止互相替代：
- Timing 不適合，不代表 Need 歸零。
- Need 很高，不代表可突破靜音或全螢幕限制。
- 沒有輸入，不代表已完成休息。

#### 5.5.2 可信重設事件

可將休息需求歸零的事件只有：
1. `BreakCompleted`：完整完成設定的 Break Guide。
2. `IdleStarted`：未操作達離席門檻，確認工作狀態已中斷。
3. 應用程式首次啟動或使用者明確執行「重設本次週期」。

以下事件不得清除需求：
- `PassivePauseDetected`
- `ReminderSnoozed`
- `ReminderIgnored`
- `ReminderAutoDismissed`
- `BreakCancelled`
- 進入或離開 Focus Mode
- 情境規則切換

#### 5.5.3 休息債務分級呈現

門檻皆為「自上次可信重設事件起算的總有效工作時間」：

| 等級 | 預設總有效工作時間 | 建議呈現強度 |
|---|---:|---|
| 0 | 0–未達工作提醒間隔 | 一般系統列狀態 |
| 1 | 20 分鐘 | 系統列靜態微狀態 |
| 2 | 35 分鐘 | 更明確的靜態圖示／Tooltip，不彈窗 |
| 3 | 45 分鐘 | Timing 符合時允許邊緣浮窗 |
| 4 | 60 分鐘 | Timing 符合且使用者允許時，可加入輕提示音與邊緣浮窗 |

實際強度計算：

```text
EffectiveIntensity =
    min(DebtRecommendedIntensity, ContextCap, UserChannelCap)
```

- 最大等待到期只影響 Timing，不改變 `EffectiveIntensity`。
- 系統列不得閃爍、跳動、顯示未讀紅點或持續動畫。
- 等級除色調外，須有靜態形狀／徽記或 Tooltip 文字差異。

#### 5.5.4 提醒嘗試與冷卻

- Snooze：使用使用者選擇的延後時間。
- Ignore／AutoDismissed：啟動「提醒重試冷卻時間」，不重設 Need。
- 若冷卻結束時間晚於下一債務等級門檻，應在該門檻時重新評估，而不是繼續沉默。
- 同一時刻最多存在一個提醒嘗試，不累積補發佇列。

### 5.6 Pause、Focus Mode 與 Disabled 的時間語義

| 模式 | 有效工作時間 | 休息需求 | 主動提醒 |
|---|---|---|---|
| Pause | 停止累積 | 停止累積，保留既有值 | 完全抑制 |
| Focus Mode | 持續累積 | 持續累積 | 完全抑制，結束後最多一次 |
| Disabled | 停止累積 | 不保留執行中週期；重新啟用時建立新週期 | 不執行 |
| Idle | 停止累積 | 進入時清除 | 不執行 |

Pause 恢復後沿用暫停前的需求值；Focus Mode 結束後若需求到期，回到 `PendingReminder` 等待自然停頓。

### FR-002 有效工作時間偵測

#### 說明
透過 Windows API 取得最後輸入時間，計算使用者實際操作電腦的時間。本功能只量測時間戳記，不得延伸為輸入頻率、節奏或模式分析。

#### 規則
- 有鍵盤或滑鼠活動且未處於 Pause／Disabled／Idle 時，累積有效工作時間。
- 未操作達被動停頓門檻時，僅觸發 `PassivePauseDetected`。
- 未操作達離席門檻時，進入 `Idle`，停止累積並清除休息需求。
- 不記錄按鍵內容、按鍵間隔、滑鼠軌跡、速度或範圍。
- 鎖定、休眠、登出時停止累積，並依平台事件結束當前工作區段。
- 喚醒或解鎖後建立新工作週期，不補發過期提醒。

#### 驗收條件
- 20 秒無輸入但未達 2 分鐘時，不進入 `Idle`、不記為完成休息、不清除債務。
- 達離席門檻後正確進入 `Idle` 並重設需求。
- Pause 不累積；Focus Mode 仍累積。
- 程式碼審查確認沒有輸入模式分析。

### FR-003 提醒狀態機

#### 狀態
```text
Disabled
Paused
Working
PendingReminder
ReminderVisible
BreakInProgress
Snoozed
Idle
FocusMode
```

#### 主要轉移
```text
Disabled
  -> Working              使用者重新啟用，建立新週期

Working
  -> PendingReminder      Need 達 Level 1
  -> Idle                 未操作達離席判定
  -> Paused               使用者暫停
  -> FocusMode            使用者啟用專注模式
  -> Disabled             使用者停用

PendingReminder
  -> ReminderVisible      Timing 可提醒且 EffectiveIntensity 允許浮窗
  -> PendingReminder      PassivePauseDetected；保持到期但隱藏可見 UI
  -> Idle                 未操作達離席判定，清除 Need
  -> Paused
  -> FocusMode
  -> Disabled

ReminderVisible
  -> BreakInProgress      使用者開始休息
  -> Snoozed              使用者延後
  -> PendingReminder      使用者忽略、AutoDismissed 或 PassivePauseDetected
  -> Idle                 未操作達離席判定
  -> Paused
  -> FocusMode
  -> Disabled

BreakInProgress
  -> Working              完整完成，清除 Need
  -> PendingReminder      取消／提前結束，不清除 Need
  -> Idle                 達離席判定

Snoozed
  -> PendingReminder      延後時間到
  -> Idle
  -> Paused
  -> FocusMode
  -> Disabled

Idle
  -> Working              使用者恢復操作，建立新週期

Paused
  -> Working/PendingReminder  恢復後依既有 Need 判定

FocusMode
  -> Working/PendingReminder  結束後依 Need 判定，最多一個提醒嘗試
```

#### 驗收條件
- 每個轉移皆可單元測試。
- `PassivePauseDetected`、`BreakCancelled`、Ignore、AutoDismissed 均不清除 Need。
- `BreakCompleted`、`IdleStarted` 才清除 Need。
- 任何時刻只有一個主要狀態與一個提醒嘗試。
- 重啟不恢復過期可見提醒。

### FR-004 自然停頓提醒

#### 說明
本需求只負責 Timing，不決定 Need 是否清除，也不直接決定 UI 通道。

#### 規則
- Need 達 Level 1 後進入 `PendingReminder`。
- 連續無輸入達自然停頓門檻時，Timing 為可提醒。
- 最大等待到期後，Timing 亦為可提醒，但呈現仍受 Intensity 與情境上限控制。
- 被動停頓達門檻時，不視為完成休息；若有可見浮窗則淡出，維持 `PendingReminder`。
- 恢復操作後不得立即彈出，需等待下一個自然停頓。
- 最大等待不得形成強制彈窗或突破全螢幕／靜音規則。

#### 驗收條件
- 持續輸入時不顯示浮窗。
- 自然停頓後 1 秒內完成提醒決策。
- 最大等待到期不會無限延期，也不會越權提升 Intensity。
- 20 秒無輸入不清除 Need。

### FR-004a 休息債務分級呈現

#### 說明
依 5.5 計算 Need 等級，提供呈現強度建議，不決定提醒時機。

#### 規則
- 等級門檻使用自上次可信重設事件起算的總有效工作時間。
- 情境上限與使用者通道設定優先。
- Level 1、2 只更新靜態系統列狀態。
- Level 3 才允許自然停頓時顯示邊緣浮窗。
- Level 4 只有在使用者允許聲音且情境未靜音時，才可加入輕提示音。
- 系統列狀態不得閃爍、呼吸、跳動或顯示未讀紅點。
- 不得只用顏色；須搭配靜態形狀、徽記或 Tooltip。

#### 驗收條件
- Fake Clock 可測試 Level 0–4。
- 最大等待不會使 Level 1、2 越級顯示浮窗。
- 全螢幕、靜音、Pause、Focus Mode 可正確限制通道。
- 門檻必須遞增且 Level 1 等於工作提醒間隔。

### FR-005 非阻擋式邊緣提醒

#### 說明
顯示於主要螢幕邊緣的小型半透明提示。

#### UI 要求
- 預設位於螢幕右側中央。
- 不顯示在工作列上方的主要操作區。
- 不成為 Active Window。
- 不搶鍵盤焦點。
- 不遮住大量內容。
- 可拖曳位置。
- 支援多螢幕，預設顯示於目前前景視窗所在螢幕。
- 顯示達「邊緣提示顯示時間」上限仍無回應時，自動淡出並記錄為 `AutoDismissed`。
- 操作按鈕採「圖示 + 極短文字」組合（例如眼睛圖示 + 「開始休息」），不得只用純圖示，避免辨識歧義；也不得使用完整句子說明，維持 0.3 秒可辨識的目標。

#### 操作
- `開始 20 秒`
- `延後 5 分鐘`
- `本次忽略`

#### 驗收條件
- 提醒出現時，使用者原本輸入中的視窗仍保持焦點。
- 鍵盤輸入不得進入提示視窗。
- 使用者可透過滑鼠操作提示。
- 全螢幕時不得顯示一般浮窗。
- 多螢幕切換後應顯示於正確螢幕。
- 逾時無回應會自動結束，且不得無限停留佔用畫面。

### FR-006 休息引導（v1.3）

#### 說明
提供不需要持續注視螢幕的完整遠眺引導。只有完成設定時長才算完成休息。

#### MVP 模式
- 節奏提示音（預設）
- 簡短語音
- 無數字進度光暈（可完全關閉）

#### Optional Experiment
- Windows Spatial Audio：預設關閉，不屬於發布阻塞條件；只有在獨立實驗開關開啟時可使用。

#### 驗收條件
- 全流程無數字倒數。
- 完整完成記為 `BreakCompleted` 並清除 Need。
- 提前結束記為 `BreakCancelled`，不清除 Need。
- 支援明確取消操作與專用快捷鍵，不使用滑鼠移動幅度推論。
- 不遮蔽、不模糊、不降黑、不阻止其他操作。
- 音訊失敗時降級為無數字視覺模式。

### FR-007 延後、忽略與逾時未回應

#### 延後
- 延後指定時間後重新進入 `PendingReminder`。
- 不清除 Need。
- 延後期間不顯示提醒，但 Need 繼續依有效工作時間累積。

#### 忽略
- 記錄 `ReminderIgnored`。
- 隱藏本次提醒，啟動 Reminder Retry Cooldown。
- 不清除 Need、不重設連續工作時間。

#### AutoDismissed
- 顯示時間到期後記錄 `ReminderAutoDismissed`。
- 隱藏本次提醒，啟動 Reminder Retry Cooldown。
- 不等同主動忽略，不清除 Need。

#### 重試冷卻
- 預設 20 分鐘，可設定。
- 若下一債務等級門檻較早到達，於該門檻重新評估。
- 冷卻期間仍可由使用者手動開始休息。
- 不建立補發佇列。

#### 驗收條件
- 三種結果互斥並可分別查詢。
- 全部均不被計為完成休息。
- Ignore／AutoDismissed 後 Need 持續累積。

### FR-008 暫停與專注模式

#### 暫停模式
- 可選 15 分鐘、30 分鐘、1 小時或直到手動恢復。
- 暫停期間停止有效工作時間與 Need 累積。
- 保留進入 Pause 前的 Need 值。
- 恢復後依既有 Need 回到 `Working` 或 `PendingReminder`。

#### 專注模式
- 預設 60 分鐘。
- 有效工作時間與 Need 持續累積。
- 不顯示浮窗、不播放聲音，只保留非動畫系統列狀態。
- 結束後若 Need 已到期，最多建立一個 `PendingReminder`，等待自然停頓。

#### 驗收條件
- Pause 與 Focus Mode 的時間語義不可混用。
- Focus Mode 期間不產生可見提醒。
- 恢復後不補發多個提醒。

### FR-009 情境規則

#### 支援規則
使用者可針對 Process Name 設定：
- 正常提醒
- 只顯示系統列
- 完全靜音
- 使用自訂提醒間隔

#### 計時器行為
- 切換到套用「自訂提醒間隔」的前景程式時，**沿用目前已累積的工作時間**，僅將「達到提醒門檻」的判斷標準換成該程式的自訂間隔值，不重新歸零計時。
- 切換離開該前景程式、回到一般規則時，同樣沿用累積時間，改用全域工作提醒間隔判斷。
- 此規則不適用於「完全靜音」與「只顯示系統列」——這兩種規則不影響計時累積，只影響是否顯示提醒。
- **休息債務累積不受情境規則切換影響（見 5.5.1，情境規則屬於「呈現強度」上限，不是「休息需求」的一部分）。**

#### 預設行為
- 偵測全螢幕時自動降級。
- 不預設判斷所有會議軟體，避免誤判。
- 可提供建議規則，但必須由使用者確認。
- **不引入任何基於輸入模式的「建議規則」推論（見原則 9）；建議規則只能依 Process Name 的已知清單提供，不得依行為分析產生。**

#### 驗收條件
- 規則應依前景 Process 生效。
- Process 結束後恢復一般模式，且工作時間累積不因規則切換而被重置或重複計算。
- 規則不得記錄視窗內容或文件名稱，除非未來版本另行審查隱私風險。

---

### FR-010 每日統計（AutoDismissed 獨立呈現，維持被動查看原則）

#### 顯示資料
- 今日有效電腦使用時間。
- 完整完成 Break Guide 次數。
- 明確離席重設次數。
- 被動停頓偵測次數（不得列入完成休息）。
- 延後次數。
- 忽略次數（主動）。
- 逾時未回應次數（AutoDismissed，被動）。
- 最長連續工作時間。
- 平均工作週期。
- 各時段提醒結果。
- 各程式的累積使用時間，可選擇關閉。

#### 設計原則
- 不提供帶有醫療暗示的健康分數。
- 不使用羞辱或責備語氣。
- 洞察必須可操作。
- 主動忽略與逾時未回應必須分開呈現，避免把「使用者根本沒看到」誤判為「使用者不想休息」。
- **統計頁僅能是使用者主動開啟才可見的資訊。不得有紅點、未讀提示、或任何形式的主動彈出摘要（呼應 4.2 新增的排除項目）。**

#### 範例
> 今天完成 9 次遠眺（其中 3 次為離開座位時自然完成）。
> 下午 2:00–4:00 有兩段超過 45 分鐘的連續使用。
> 這段時間有 4 次提醒逾時無回應，可能提醒位置不夠明顯。

#### 驗收條件
- 統計值可由事件紀錄重算。
- 刪除資料後統計應同步更新。
- 使用者可關閉各程式使用統計。
- 主動忽略與 AutoDismissed 的次數在資料庫層級即為不同事件類型，不需在統計層另行推斷。
- **統計頁不得在系統列圖示上疊加數字或紅點徽章。**

### FR-011 設定

#### 一般
- 開機自動啟動
- 啟動時最小化
- 語言
- 深色／淺色模式
- 通知音量
- 重設設定

#### 提醒
- 工作間隔
- 遠眺時間
- 延後時間
- 自然停頓判定
- 最大等待時間
- 離席判定
- 被動停頓判定（須 < 離席判定，違反時即時提示並拒絕儲存）
- 提醒位置
- 透明度
- 提示模式（含空間音效選用開關）

#### 隱私與資料

- 檢視資料位置
- 匯出資料
- 清除全部資料
- **快速連結至「目前系統知道什麼」檢視（見 FR-012）**

#### 驗收條件
- 設定修改後應即時或在明確標示的下次週期生效。

- 重設設定不得自動刪除歷史資料。

### FR-012 資料透明檢視（v1.2 新增）

#### 說明
提供一個比設定頁更容易到達的入口，讓使用者能在系統列點擊兩次以內，看到「系統目前實際蒐集了什麼」，降低監控感疑慮（見 R-12）。這不是隱私政策文字頁，而是即時反映目前狀態與資料量的檢視畫面。

#### 顯示內容
- 目前是否記錄前景程式名稱（開／關）。
- 目前本機資料庫的事件筆數與佔用空間。
- 最近一次資料匯出或清除的時間。
- 明確列出「目前不會被蒐集」的項目清單（按鍵內容、滑鼠軌跡、畫面截圖、視窗文字、網址、文件名稱、攝影機或麥克風資料、輸入節奏與滑鼠移動模式分析）。

#### 驗收條件
- 從系統列圖示到此畫面，點擊次數不得超過兩次。
- 顯示內容須與 NFR-003 實際行為一致，不得只是靜態文字。
- 此畫面本身不觸發任何新的資料蒐集。

## 7. 非功能需求

### NFR-001 效能（補充實作建議）

- 背景閒置 CPU 平均使用率目標低於 0.5%。
- 記憶體使用量目標低於 150 MB。
- 不得每秒頻繁寫入 SQLite，事件可緩衝後批次寫入。
- 不得使用全域低階鍵盤 Hook 取得按鍵內容。
- **實作建議**：`GetLastInputInfo` 等活動偵測應以計時器輪詢（建議每 1 秒一次），而非持續監聽或高頻率事件回呼；系統列狀態應以事件驅動的靜態圖示切換為主，不得持續播放呼吸、閃爍或漸變動畫；必要的短暫淡入淡出不得超過 10 FPS，完成後停止渲染。

### NFR-002 穩定性

- 單一背景服務異常不得造成整個程式反覆崩潰。
- SQLite 寫入失敗需保留錯誤紀錄，不得阻塞 UI。
- 提醒視窗建立失敗時，應降級為系統通知或系統列狀態。
- 應處理 Windows 睡眠、喚醒、鎖定與螢幕配置變更。
- 任一音訊播放失敗時，應降級為無數字視覺模式，不得阻塞 Break Guide 流程。

### NFR-003 隱私（v1.2 補充：明訂行為建模排除範圍）

預設不收集：
- 按鍵內容
- 滑鼠位置軌跡
- 畫面截圖
- 視窗文字
- 網址
- 文件名稱
- 攝影機或麥克風資料
- **輸入節奏、輸入頻率變化、滑鼠移動速度或範圍等模式性特徵（不論是否落地儲存，均不得在背景持續分析，見原則 9、R-11）**

前景程式名稱紀錄：
- **預設關閉**。
- 首次設定中明確說明用途與影響（例如關閉後無法使用情境規則）。
- 使用者可隨時開啟或關閉。
- 僅儲存 Process Name 與時間，不儲存 Window Title。

**資料可見性**：使用者必須能透過 FR-012 以低於兩次點擊的路徑，隨時查看目前實際蒐集的資料類型，而不只是在隱私權政策文字中被告知一次。

### NFR-004 可測試性

- 計時器必須透過 `IClock` 抽象注入。
- Windows 狀態偵測必須有 Interface，可用 Fake 實作測試。
- 狀態機不可直接依賴 UI。
- SQLite Repository 必須可替換成 In-Memory 實作。
- Reminder Presenter 必須與提醒決策分離。
- **「休息需求」「提醒時機」「呈現強度」三個模組（見 5.5.1）必須各自可獨立單元測試，不得合併成單一決策函式，以避免邏輯混淆難以驗證。**

### NFR-005 無障礙

- 所有設定控制項可使用鍵盤操作。
- 支援 Windows 顯示縮放 100%–200%。
- 不只用顏色表示狀態。
- 提供降低動畫或關閉動畫選項。
- 文字與背景需保持合理對比。
- 休息引導的聽覺模式須提供純視覺替代（無數字進度光暈），供聽覺不便使用者使用。

## 10. 事件與統計定義

### 10.1 有效工作時間

有效工作時間：
- 使用者未處於 Idle。
- 系統未鎖定。
- 程式未暫停或停用。
- 不在「完全忽略統計」的情境。
- 以時間區段計算，不以鍵盤事件數量計算。

### 10.2 可信休息與重設事件

#### 完整休息
- 使用者完整完成 Break Guide（`BreakCompleted`）。

#### 明確離席
- 未操作達離席判定並進入 `Idle`（`IdleStarted`）。
- 這是產品為了簡化 MVP 所採用的保守代理事件，不代表系統證明使用者有遠眺；統計必須與 `BreakCompleted` 分開。

#### 非完成事件
以下不得計為完成休息，也不得清除 Need：
- `PassivePauseDetected`
- `BreakCancelled`
- `ReminderSnoozed`
- `ReminderIgnored`
- `ReminderAutoDismissed`

### 10.3 連續工作時間

從上一次 `BreakCompleted`、`IdleStarted`、程式建立新週期或使用者明確重設開始計算。
- Pause 期間停止計算，恢復後延續原值。
- Focus Mode 期間持續計算。
- PassivePauseDetected、延後、忽略與 AutoDismissed 不會中斷連續工作。

### 10.4 休息債務等級

休息債務等級反映「自上次可信重設事件起的總有效工作時間」。
- Level 1 必須等於工作提醒間隔。
- 等級變化記錄為 `RestDebtLevelChanged`。
- 此事件只供 UI 狀態與統計，不得用來推論專注狀態。
- 統計必須分開呈現 `BreakCompleted`、`IdleStarted` 與 `PassivePauseDetected`。

## 11. 錯誤與降級策略

| 問題 | 降級行為 |

## 13. 測試策略

### 13.1 單元測試

必測：
- 工作時間累積。
- Idle 進入與離開。
- 被動停頓判定觸發：20 秒只記錄停頓並隱藏過期 UI，不清除 Need。
- 20 分鐘門檻。
- 自然停頓判定。
- 最大等待時間。
- 延後、忽略、AutoDismissed 三種結果互斥且正確記錄，且均不清除休息債務。
- 休息債務四個等級的累積與清除邏輯（含全螢幕、暫停、專注模式期間持續累積）。
- 情境上限優先於債務等級（例如靜音規則下即使債務達最高等級仍不彈窗）。
- 全螢幕降級。
- 暫停、專注模式與其回復轉移。
- 停用（Disabled）與回復轉移。
- 休息完成後重設。
- 系統睡眠／喚醒後狀態。
- 設定值邊界，包含「被動停頓判定 ≥ 離席判定」、Level 1 不等於工作提醒間隔與債務門檻未遞增。
- Review Trigger 計算。
- 情境規則切換時工作時間不歸零。
- 「休息需求」「提醒時機」「呈現強度」三個模組各自獨立測試，並測試三者組合時不互相覆蓋（見 5.5.1、NFR-004）。

### 13.2 整合測試

- SQLite Migration。
- Event Repository 寫入與查詢（含新索引效能）。
- 設定持久化。
- 應用規則套用。
- 啟動與關閉。
- 系統列生命週期，含休息債務圖示狀態切換。
- 資料透明檢視內容與實際資料庫狀態一致性（見 FR-012）。

### 13.3 手動測試

- VS Code 中持續打字 20 分鐘。
- 全螢幕 YouTube 或簡報。
- 雙螢幕切換。
- Windows 顯示縮放 125%、150%、200%。
- 鎖定與解鎖。
- 睡眠與喚醒。
- 改變主要螢幕。
- Remote Desktop。
- 高 DPI 與不同解析度。
- 提醒出現時持續在 IDE 中輸入。
- 提醒視窗可點擊但不搶焦點。
- 提醒顯示後完全不理會，確認 30 秒後正確 AutoDismissed。
- 短暫無輸入 20–30 秒後恢復，確認只觸發 `PassivePauseDetected`，不進入 Idle、不清除 Need、且不立即彈窗。
- 連續忽略多次提醒，觀察系統列債務等級圖示是否隨時間正確升級。
- 若實驗版包含 Spatial Audio，確認其不可用時不影響核心 Break Guide；正式 MVP 可完全不包含此功能。
- 從系統列開啟「目前系統知道什麼」，確認兩次點擊內可達且內容與實際設定一致。

## 14. MVP 驗收標準

MVP 可發布的最低條件：

1. 可在 Windows 10 / 11 穩定常駐 8 小時。
2. 提醒視窗不搶前景程式焦點。
3. 不攔截或停用鍵盤滑鼠。
4. 可正確處理工作、短暫被動停頓、明確離席、延後、忽略、AutoDismissed、BreakCompleted 與 BreakCancelled。
5. 全螢幕時自動降級。
6. 系統睡眠或解鎖後不產生異常提醒。
7. 所有核心狀態轉移（含新增的回復轉移）具有單元測試。
8. 本機資料可清除。
9. 前景程式統計預設關閉，可由使用者開啟。
10. 休息債務分級邏輯、系統列微狀態呈現，以及三個獨立決策模組（需求／時機／強度）均通過單元測試。
11. 資料透明檢視可正確反映目前蒐集狀態，且兩次點擊內可達。
12. Break Guide 全流程不含數字倒數，且只有完整完成才清除 Need。
13. 無 Critical 或 High 等級已知缺陷。
14. 日常背景 CPU 與記憶體符合 NFR。
15. 完成至少 5 個工作日的 Dogfooding。

## 15. 價值驗證指標

以下不是工程完成條件，而是產品假設驗證：

| 指標 | 初始觀察目標 | 說明 |
|---|---:|---|
| 7 日持續啟用率 | 不先設硬門檻 | 初期樣本可能只有單一使用者 |
| Break Guide 完成率 | 觀察趨勢 | `BreakCompleted`／已顯示可操作提醒 |
| 延後率 | 觀察時段差異 | 延後 / 顯示 |
| 主動忽略率 | 觀察趨勢 | 忽略 / 顯示 |
| 逾時未回應率（AutoDismissed） | 觀察趨勢 | 用來判斷提醒能見度是否足夠，而非使用者意願 |
| 連續工作超過 60 分鐘次數 | 比基準下降 | 不要求歸零 |
| **各休息債務等級的實際提醒結果分布** | 觀察趨勢 | 用以評估債務等級門檻是否需要調整，亦作為未來評估是否需要更細緻情境判斷（如深度工作偵測）的實證基礎 |
| 主觀干擾評分 | 每日 1–5 | 越低越好 |
| 主觀眼睛疲勞 | 每日 1–5 | 僅供自我追蹤，不是醫療指標 |
| 主動關閉提醒功能次數 | 觀察原因 | 找出過度干擾情境 |
| **主動開啟「目前系統知道什麼」次數** | 觀察趨勢 | 若使用者頻繁查看，可能反映監控疑慮尚未被充分緩解 |

不得把上述數字直接宣稱為健康效果。主動忽略率與逾時未回應率必須分開判讀：前者反映使用者意願，後者可能反映提醒本身能見度不足，兩者對應的改善方向不同。

## 16. Review Trigger

下列條件發生時，需求不會自動失效，但必須進入 Review Backlog：

- 連續 5 個工作日忽略率（含主動忽略與逾時未回應）明顯高於完成率。
- 使用者頻繁使用暫停或結束程式逃避提醒。
- 全螢幕或特定應用的誤判明顯。
- 背景 CPU、記憶體或電池消耗超標。
- 使用者表示提醒仍會搶焦點或遮擋內容。
- 產品原則與價值目標出現衝突。
- Windows API 或平台行為變更。
- 收到隱私、安全或法規風險回報。
- MVP Dogfooding 滿 10 個工作日。
- 被動停頓判定造成過多提醒淡出／重新出現，或離席門檻造成不合理的 Need 重設。
- **（v1.2 新增）休息債務等級 3、4 頻繁出現且完成率偏低，顯示「寧可晚一點提醒」的策略在實測中可能造成過多深度打斷——此時應優先評估是否需要引入 Windows Focus Assist 整合等既有系統訊號，而非直接跳到自製的行為模式分析。**
- **（v1.2 新增）「目前系統知道什麼」被頻繁主動開啟，顯示監控疑慮仍存在，需檢視是否有其他未被察覺的信任缺口。**

### 權限原則
- 任何 Agent 或團隊成員均可提出 Review（挑戰權不分層）。
- 可調參數可由工程與產品根據數據直接調整。
- 版本承諾須在 Sprint Planning 或 Review 中修改。
- 產品原則須由產品、工程與使用者代表共同審查。
- 安全、隱私、資料損失問題可立即中止當期開發或發布。

# 19. Agent 執行規則

其他 Agent 開工時應遵守：

1. 不得自行加入 Out of Scope 功能，特別是任何形式的輸入節奏或滑鼠模式分析（見原則 9）。
2. 技術細節可調整，但不得違反產品原則。
3. 若發現需求矛盾，建立 Decision Record，不得默默自行解釋。
4. 所有可調數值必須配置化。
5. 核心時間邏輯必須使用 Fake Clock 測試。
6. UI 不得包含任何強制阻擋操作，包括畫面模糊化或降黑。
7. 不得記錄 Window Title、鍵盤內容、畫面內容或行為模式特徵。
8. 每完成一個 Backlog Item，必須附：變更摘要、測試結果、已知限制、是否影響需求或資料結構。
9. 若要修改產品原則或 MVP Scope，必須提出：問題證據、影響範圍、替代方案、不修改的成本。
10. 安全、隱私、資料損失問題可立即中止開發並要求 Review。
11. **「休息需求」「提醒時機」「呈現強度」三個決策模組必須維持獨立，任何試圖合併三者的重構提案，須先建立 Decision Record 並說明理由。**

# 20. Definition of Done

每個 Backlog Item 完成時必須符合：

- 程式碼已完成。
- 單元測試或整合測試已新增。
- 所有既有測試通過。
- 無新增編譯警告。
- 已處理錯誤與降級情境。
- 日誌不包含敏感資訊或行為模式特徵。
- UI 符合不搶焦點與無障礙要求，且不含數字倒數（如涉及 Break Guide）。
- 文件同步更新。
- 已知限制已明確記錄。
- 可由另一名 Agent 根據驗收條件重現結果。
