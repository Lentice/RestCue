## 2. 產品摘要

### 2.1 一句話定位

一個常駐 Windows 背景、能判斷使用者是否持續工作，並在自然停頓點提供不搶焦點、不遮蔽內容、可延後的護眼提醒工具。

### 2.2 使用者問題

長時間使用電腦時，使用者容易：

- 忘記依照 20-20-20 原則遠眺。
- 因專注而長時間不休息或減少眨眼。
- 對固定時間、突然跳出的提醒感到干擾。
- 在會議、簡報、全螢幕或高專注工作時不希望被打斷。
- 安裝提醒工具後，因提醒過於煩人而關閉軟體。

### 2.3 產品目標

MVP 要驗證：

1. 非阻擋式提醒是否能長期保持啟用。
2. 智慧等待自然停頓是否比固定時間直接跳出更不干擾。
3. 使用者是否會實際執行 20 秒遠眺。
4. 哪些工作情境最容易忽略或延後提醒。

## 3. 需求分層

### 3.1 產品原則

以下原則為高穩定層，MVP 內不得違反：

1. 不得封鎖、停用或攔截鍵盤與滑鼠。
2. 不得使用全螢幕遮罩阻止使用者工作。
3. 不得顯示必須處理後才能繼續工作的 Modal Dialog。
4. 提醒不得搶走目前應用程式的輸入焦點。
5. 使用者必須能忽略、延後或關閉提醒。
6. 所有行為資料預設只儲存在本機。
7. 不記錄鍵盤輸入內容、剪貼簿內容、畫面內容或網站內容。
8. 不把產品描述為醫療診斷或治療工具。

### 3.2 MVP 版本承諾

MVP v1.1 必須交付：

- 系統列常駐程式。
- 有效工作時間偵測。
- 閒置（Idle）與被動休息偵測（兩個獨立機制，見 3.3）。
- 20-20-20 計時狀態機。
- 等待自然輸入停頓後再提醒。
- 不搶焦點的螢幕邊緣提醒。
- 開始休息、延後、本次忽略三種操作，以及提醒逾時未回應的自動結束。
- 20 秒無畫面依賴的休息引導。
- 全螢幕情境自動降級提醒。
- 暫停與專注模式。
- 每日基本統計。
- 本機設定與資料儲存。
- 開機自動啟動選項。

### 3.3 可調參數

以下參數必須配置化，不得硬編碼在 UI 邏輯中：

| 參數 | 預設值 | 可調範圍 | 備註 |
|---|---:|---:|---|
| 工作提醒間隔 | 20 分鐘 | 10–60 分鐘 | |
| 自然停頓判定 | 5 秒 | 2–30 秒 | 用於決定何時顯示已到期的提醒 |
| 最大等待提醒時間 | 3 分鐘 | 0–10 分鐘 | |
| 遠眺時間 | 20 秒 | 10–60 秒 | |
| 延後時間 | 5 分鐘 | 1–30 分鐘 | |
| **離席判定（Idle Threshold）** | 2 分鐘 | 1–10 分鐘 | 進入 `Idle` 狀態、停止累積工作時間的門檻 |
| **被動休息判定（Passive Break Threshold）** | 20 秒 | 10–120 秒 | 判斷一次短暫離開是否可算作完成休息、重設提醒週期。**必須 ≤ 離席判定**，設定畫面須驗證此關係 |
| 邊緣提示顯示時間 | 30 秒 | 5–120 秒 | 超過此時間無回應，視為 `AutoDismissed`（見 FR-003） |
| 提示透明度 | 70% | 20–100% | |
| 每日摘要時間 | 關閉 | 使用者設定 | |

> **R-01 說明**：離席判定與被動休息判定是兩件不同的事。離席判定決定「使用者是否離開電腦、應停止累積工作時間」；被動休息判定決定「這次離開夠不夠久，可以算作一次自然休息」。因為使用者可能離開電腦 25 秒（超過被動休息判定但未達離席判定），這種情況下工作時間累積仍可能被視為連續（未進入 Idle），但已足以重設下一次提醒的等待。兩者互相獨立，但為避免使用者設定出矛盾（被動休息判定 > 離席判定），必須在設定驗證中擋下。

## 5. 核心使用流程

### 5.1 正常提醒流程

1. 程式在系統列常駐。
2. 使用者開始操作鍵盤或滑鼠。
3. 系統累積有效工作時間。
4. 累積達提醒門檻後，狀態轉為 `PendingReminder`。
5. 系統等待使用者連續停止輸入 5 秒（自然停頓判定）。
6. 若在最大等待 3 分鐘內出現自然停頓，顯示邊緣提醒。
7. 若超過 3 分鐘仍無停頓，顯示較低干擾程度的提醒。
8. 使用者可選擇：
   - 開始 20 秒休息。
   - 延後 5 分鐘。
   - 本次忽略。
   - 不回應：提醒顯示滿「邊緣提示顯示時間」（預設 30 秒）後自動結束，記錄為 `AutoDismissed`（見 FR-003）。
9. 系統記錄結果並重新計算下一週期。

### 5.2 離席與被動休息流程（已修正）

本流程涉及兩個獨立門檻，請對照 3.3 的說明：

1. 使用者停止操作。
2. 系統持續計算「未操作時長」。
3. **若未操作時長達到「被動休息判定」（預設 20 秒）**：無論是否已進入 Idle，只要目前狀態為 `PendingReminder` 或 `ReminderVisible`，都視為完成一次被動休息（`PassiveBreakCompleted`），取消當次提醒並重設下一次工作週期。
4. **若未操作時長持續達到「離席判定」（預設 2 分鐘）**：狀態轉為 `Idle`，停止累積工作時間，系統列圖示反映離開狀態。
5. 使用者恢復操作：
   - 若先前處於 `Idle`，狀態轉回 `Working`，並依步驟 3 的結果決定是否已完成被動休息。
   - 不應在使用者離席期間持續產生新的提醒。

### 5.3 全螢幕流程

1. 系統偵測前景視窗為全螢幕。
2. 到達提醒時間後，不顯示螢幕邊緣浮窗。
3. 改以系統列圖示變化或可選的輕提示音提醒。
4. 使用者離開全螢幕後，若提醒仍有效，再顯示一般提醒。
5. 不得主動退出、最小化或切換全螢幕程式。

### 5.4 休息引導流程

開始休息後：

- 不顯示需要注視的倒數大畫面。
- 可使用提示音、語音或小型倒數。
- 預設引導：
  - 0 秒：看向約 6 公尺外的物體。
  - 5 秒：慢慢眨眼兩次。
  - 10 秒：換一個較遠的位置。
  - 15 秒：放鬆眼睛與肩膀。
  - 20 秒：播放完成提示。
- 使用者可隨時提前結束。
- 結束後記錄為 `Completed`。

## 6. 功能需求

### FR-001 系統列常駐

#### 說明
程式啟動後常駐 Windows 系統列，不顯示主視窗。

#### 系統列選單
- 開啟狀態頁
- 立即開始 20 秒休息
- 延後下一次提醒
- 暫停提醒
- 專注模式
- 停用程式（對應 `Disabled` 狀態，見 FR-003）
- 設定
- 結束程式

#### 驗收條件
- 關閉主視窗不得退出程式。
- 系統列圖示應反映目前狀態，包含 `Disabled`。
- 結束程式必須明確由選單或設定執行。

---

### FR-002 有效工作時間偵測

#### 說明
透過 Windows API 取得最後輸入時間，計算使用者實際操作電腦的時間。

#### 規則
- 有鍵盤或滑鼠活動時累積工作時間。
- 未操作時長達到「離席判定」門檻後進入 Idle，停止累積。
- 未操作時長達到「被動休息判定」門檻後（可能早於離席判定），若當時正處於等待提醒或提醒顯示中，觸發被動休息重設（詳見 5.2）。
- 不記錄按鍵內容。
- 鎖定螢幕、休眠、登出時停止累積。
- 系統喚醒或解鎖後重新開始工作週期。

#### 驗收條件
- 使用者操作時，計時器可正確累積。
- 離席後不得繼續累積。
- 離開 20 秒（被動休息判定預設值）但未滿 2 分鐘（離席判定預設值）時，不應進入 `Idle` 狀態，但若正在等待或顯示提醒，應觸發被動休息重設。
- 解鎖後不得立即使用舊的過期提醒轟炸使用者。

- `AutoDismissed` 與使用者主動「忽略」必須記錄為不同的事件類型（見 9.2）。

### FR-004 自然停頓提醒（已修正）

#### 說明
到達提醒門檻後，不立即彈出，而是等待輸入停頓。

#### 規則
- 到達工作提醒間隔（預設 20 分鐘）後轉為 `PendingReminder`。
- 連續達到「自然停頓判定」（預設 5 秒）未輸入即顯示提醒。
- 最多等待「最大等待提醒時間」（預設 3 分鐘）。
- 超過最大等待後仍可提醒，但不得搶焦點。
- 在等待期間，若未操作時長達到「被動休息判定」（預設 20 秒），取消本次提醒，視為已休息，回到 `Working` 並重新計算下一週期（不需等到離席判定的 2 分鐘）。

#### 驗收條件
- 高頻打字期間不得立即打斷。
- 自然停頓達門檻後，提醒應在 1 秒內顯示。
- 最大等待時間到後不得無限延期。
- 使用者中途離開達被動休息判定即可正確取消提醒並重設週期，不需等待離席判定門檻。

---

### FR-005 非阻擋式邊緣提醒

#### 說明
顯示於主要螢幕邊緣的小型半透明提示。

#### UI 要求
- 預設位於螢幕右側中央。
- 不顯示在工作列上方的主要操作區。
- 不成為 Active Window。
- 不搶鍵盤焦點。
- 不遮住大量內容。
- 可拖曳位置。
- 支援多螢幕，預設顯示於目前前景視窗所在螢幕。
- 顯示達「邊緣提示顯示時間」上限仍無回應時，自動淡出並記錄為 `AutoDismissed`。

#### 操作
- `開始 20 秒`
- `延後 5 分鐘`
- `本次忽略`

#### 驗收條件
- 提醒出現時，使用者原本輸入中的視窗仍保持焦點。
- 鍵盤輸入不得進入提示視窗。
- 使用者可透過滑鼠操作提示。
- 全螢幕時不得顯示一般浮窗。
- 多螢幕切換後應顯示於正確螢幕。
- 逾時無回應會自動結束，且不得無限停留佔用畫面。

### FR-006 休息引導

#### 說明
提供 20 秒遠眺引導，使用者不需要持續盯著螢幕。

#### 模式
- 提示音模式
- 語音模式
- 靜音倒數模式

#### 驗收條件
- 休息開始與結束均有清楚回饋。
- 使用者可提前結束。
- 完成後記錄結果。
- 不得全螢幕遮蔽。
- 不得強制阻止其他操作。

### FR-007 延後、忽略與逾時未回應（已修正）

#### 延後
- 預設延後 5 分鐘。
- 延後期間不重複顯示提醒。
- 延後到期後重新進入 `PendingReminder`。
- 連續延後次數應記錄。

#### 忽略（主動）
- 使用者主動點擊「本次忽略」。
- 本次提醒立即結束。
- 從忽略時間重新計算下一週期。
- 忽略次數應記錄，與 `AutoDismissed` 分開統計。

#### 逾時未回應（AutoDismissed，被動）
- 提醒顯示滿「邊緣提示顯示時間」仍無任何互動。
- 視為未完成休息，但**不等同於主動忽略**：不應被計入使用者「刻意拒絕」的統計，而是獨立記錄，供後續判斷提醒可見度或時機是否需要調整。
- 從逾時時間重新計算下一週期。

#### 驗收條件
- 延後後不得在延後時間內再次彈出。
- 忽略與 AutoDismissed 均不應被計為完成休息。
- 忽略、AutoDismissed、延後三者的次數可在統計中分別查詢。

---

### FR-008 暫停與專注模式

#### 暫停模式
使用者可選擇：
- 15 分鐘
- 30 分鐘
- 1 小時
- 直到手動恢復

#### 專注模式
- 預設 60 分鐘。
- 期間不顯示浮窗。
- 可只保留系統列狀態。
- **期間工作時間仍持續累積**，但提醒一律不顯示；結束後若已達提醒門檻，僅顯示「一次」提醒，不得因期間累積的多個週期而連續彈出。
- 時間結束後恢復一般模式。

#### 驗收條件
- 暫停期間不得出現提醒。
- 專注模式期間工作時間持續累積，但提醒被抑制。
- 恢復後重新開始合理的工作週期，不得立即彈出累積中的多個提醒。
- 專注模式剩餘時間應可查看。

---

### FR-009 情境規則（已修正：明訂切換自訂間隔時的計時器行為）

#### 支援規則
使用者可針對 Process Name 設定：
- 正常提醒
- 只顯示系統列
- 完全靜音
- 使用自訂提醒間隔

#### 計時器行為
- 切換到套用「自訂提醒間隔」的前景程式時，**沿用目前已累積的工作時間**，僅將「達到提醒門檻」的判斷標準換成該程式的自訂間隔值，不重新歸零計時。
- 切換離開該前景程式、回到一般規則時，同樣沿用累積時間，改用全域工作提醒間隔判斷。
- 此規則不適用於「完全靜音」與「只顯示系統列」——這兩種規則不影響計時累積，只影響是否顯示提醒。

#### 預設行為
- 偵測全螢幕時自動降級。
- 不預設判斷所有會議軟體，避免誤判。
- 可提供建議規則，但必須由使用者確認。

#### 驗收條件
- 規則應依前景 Process 生效。
- Process 結束後恢復一般模式，且工作時間累積不因規則切換而被重置或重複計算。
- 規則不得記錄視窗內容或文件名稱，除非未來版本另行審查隱私風險。

---

### FR-010 每日統計（已修正：AutoDismissed 獨立呈現）

#### 顯示資料
- 今日有效電腦使用時間。
- 完成休息次數（含主動休息與被動休息，分開標示）。
- 延後次數。
- 忽略次數（主動）。
- 逾時未回應次數（AutoDismissed，被動）。
- 最長連續工作時間。
- 平均工作週期。
- 各時段提醒結果。
- 各程式的累積使用時間，可選擇關閉。

#### 設計原則
- 不提供帶有醫療暗示的健康分數。
- 不使用羞辱或責備語氣。
- 洞察必須可操作。
- 主動忽略與逾時未回應必須分開呈現，避免把「使用者根本沒看到」誤判為「使用者不想休息」。

#### 範例
> 今天完成 9 次遠眺（其中 3 次為離開座位時自然完成）。
> 下午 2:00–4:00 有兩段超過 45 分鐘的連續使用。
> 這段時間有 4 次提醒逾時無回應，可能提醒位置不夠明顯。

#### 驗收條件
- 統計值可由事件紀錄重算。
- 刪除資料後統計應同步更新。
- 使用者可關閉各程式使用統計。
- 主動忽略與 AutoDismissed 的次數在資料庫層級即為不同事件類型，不需在統計層另行推斷。

### FR-011 設定

#### 一般
- 開機自動啟動
- 啟動時最小化
- 語言
- 深色／淺色模式
- 通知音量
- 重設設定

#### 提醒
- 工作間隔
- 遠眺時間
- 延後時間
- 自然停頓判定
- 最大等待時間
- 離席判定
- 被動休息判定（須 ≤ 離席判定，違反時即時提示並拒絕儲存）
- 提醒位置
- 透明度
- 提示模式

#### 隱私與資料
- 是否記錄前景程式名稱（**預設關閉**，見 NFR-003）
- 檢視資料位置
- 匯出資料
- 清除全部資料

#### 驗收條件
- 設定修改後應即時或在明確標示的下次週期生效。
- 非法值必須被拒絕，包含「被動休息判定 > 離席判定」這類跨欄位邏輯錯誤。
- 重設設定不得自動刪除歷史資料。

## 7. 非功能需求

### NFR-001 效能（已修正：補充實作建議）

- 背景閒置 CPU 平均使用率目標低於 0.5%。
- 記憶體使用量目標低於 150 MB。
- 不得每秒頻繁寫入 SQLite，事件可緩衝後批次寫入。
- 不得使用全域低階鍵盤 Hook 取得按鍵內容。
- **實作建議**：`GetLastInputInfo` 等活動偵測應以計時器輪詢（建議每 1 秒一次），而非持續監聽或高頻率事件回呼；UI 動畫（如呼吸燈）應限制更新頻率（建議 ≤ 10 FPS），閒置時暫停動畫渲染，避免背景常駐時仍持續佔用 GPU/CPU。

### NFR-002 穩定性

- 單一背景服務異常不得造成整個程式反覆崩潰。
- SQLite 寫入失敗需保留錯誤紀錄，不得阻塞 UI。
- 提醒視窗建立失敗時，應降級為系統通知或系統列狀態。
- 應處理 Windows 睡眠、喚醒、鎖定與螢幕配置變更。

### NFR-003 隱私（已修正：前景程式名稱預設關閉）

預設不收集：
- 按鍵內容
- 滑鼠位置軌跡
- 畫面截圖
- 視窗文字
- 網址
- 文件名稱
- 攝影機或麥克風資料

前景程式名稱紀錄：
- **預設關閉**（原 v1.0 為預設開啟，本次修正為預設關閉以符合「預設不蒐集」的一致立場）。
- 首次設定中明確說明用途與影響（例如關閉後無法使用情境規則）。
- 使用者可隨時開啟或關閉。
- 僅儲存 Process Name 與時間，不儲存 Window Title。

### NFR-004 可測試性

- 計時器必須透過 `IClock` 抽象注入。
- Windows 狀態偵測必須有 Interface，可用 Fake 實作測試。
- 狀態機不可直接依賴 UI。
- SQLite Repository 必須可替換成 In-Memory 實作。
- Reminder Presenter 必須與提醒決策分離。

### NFR-005 無障礙

- 所有設定控制項可使用鍵盤操作。
- 支援 Windows 顯示縮放 100%–200%。
- 不只用顏色表示狀態。
- 提供降低動畫或關閉動畫選項。
- 文字與背景需保持合理對比。

## 10. 事件與統計定義

### 10.1 有效工作時間

有效工作時間：

- 使用者未處於 Idle。
- 系統未鎖定。
- 程式未暫停或停用。
- 不在「完全忽略統計」的情境。
- 以時間區段計算，不以鍵盤事件數量計算。

### 10.2 完成休息（已修正）

滿足以下任一條件：

- 使用者主動完成 Break Guide（`BreakCompleted`）。
- 未操作時長達到「被動休息判定」（預設 20 秒），且當時處於 `PendingReminder` 或 `ReminderVisible`（`PassiveBreakCompleted`）。

被動休息與主動完成的 Break Guide 分開記錄，避免在統計中混淆「使用者刻意執行遠眺」與「單純離開座位」。

### 10.3 連續工作時間

從上一次完成休息（主動或被動）、進入 Idle、暫停或程式啟動開始計算。

延後、忽略、AutoDismissed 均不視為休息。

## 11. 錯誤與降級策略

| 問題 | 降級行為 |
|---|---|
| SQLite 無法寫入 | 暫存記憶體、記錄錯誤、稍後重試 |
| 提醒視窗建立失敗 | 顯示系統通知或系統列狀態 |

| 設定檔損壞 | 備份後載入預設值 |
| 多螢幕定位失敗 | 顯示於主要螢幕工作區右側 |
| 被動休息判定設定值大於離席判定 | 拒絕儲存，提示使用者修正 |

## 13. 測試策略

### 13.1 單元測試

必測：

- 工作時間累積。
- Idle 進入與離開。
- 被動休息判定觸發（獨立於離席判定，含邊界情境：20 秒觸發、離席判定未達）。
- 20 分鐘門檻。
- 自然停頓判定。
- 最大等待時間。
- 延後、忽略、AutoDismissed 三種結果互斥且正確記錄。
- 全螢幕降級。
- 暫停、專注模式與其回復轉移。
- 停用（Disabled）與回復轉移。
- 休息完成後重設。
- 系統睡眠／喚醒後狀態。
- 設定值邊界，包含「被動休息判定 > 離席判定」的拒絕邏輯。
- Review Trigger 計算。
- 情境規則切換時工作時間不歸零。

### 13.2 整合測試

- SQLite Migration。
- Event Repository 寫入與查詢（含新索引效能）。
- 設定持久化。
- 應用規則套用。
- 啟動與關閉。
- 系統列生命週期。

### 13.3 手動測試

- VS Code 中持續打字 20 分鐘。
- 全螢幕 YouTube 或簡報。
- 雙螢幕切換。
- Windows 顯示縮放 125%、150%、200%。
- 鎖定與解鎖。
- 睡眠與喚醒。
- 改變主要螢幕。
- Remote Desktop。
- 高 DPI 與不同解析度。
- 提醒出現時持續在 IDE 中輸入。
- 提醒視窗可點擊但不搶焦點。
- 提醒顯示後完全不理會，確認 30 秒後正確 AutoDismissed。
- 短暫離開 20–30 秒後立即回來，確認正確觸發被動休息而非進入 Idle。

## 14. MVP 驗收標準

MVP 可發布的最低條件：

1. 可在 Windows 10 / 11 穩定常駐 8 小時。
2. 提醒視窗不搶前景程式焦點。
3. 不攔截或停用鍵盤滑鼠。
4. 可正確處理工作、離席、被動休息、延後、忽略、AutoDismissed 與主動休息。
5. 全螢幕時自動降級。
6. 系統睡眠或解鎖後不產生異常提醒。
7. 所有核心狀態轉移（含新增的回復轉移）具有單元測試。
8. 本機資料可清除。
9. 前景程式統計預設關閉，可由使用者開啟。
10. 無 Critical 或 High 等級已知缺陷。
11. 日常背景 CPU 與記憶體符合 NFR。
12. 完成至少 5 個工作日的 Dogfooding。

## 15. 價值驗證指標

以下不是工程完成條件，而是產品假設驗證：

| 指標 | 初始觀察目標 | 說明 |
|---|---:|---|
| 7 日持續啟用率 | 不先設硬門檻 | 初期樣本可能只有單一使用者 |
| 提醒完成率 | 觀察趨勢 | 完成（含被動）／ 顯示 |
| 延後率 | 觀察時段差異 | 延後 / 顯示 |
| 主動忽略率 | 觀察趨勢 | 忽略 / 顯示 |
| 逾時未回應率（AutoDismissed） | 觀察趨勢 | 用來判斷提醒能見度是否足夠，而非使用者意願 |
| 連續工作超過 60 分鐘次數 | 比基準下降 | 不要求歸零 |
| 主觀干擾評分 | 每日 1–5 | 越低越好 |
| 主觀眼睛疲勞 | 每日 1–5 | 僅供自我追蹤，不是醫療指標 |
| 主動關閉提醒功能次數 | 觀察原因 | 找出過度干擾情境 |

不得把上述數字直接宣稱為健康效果。主動忽略率與逾時未回應率必須分開判讀：前者反映使用者意願，後者可能反映提醒本身能見度不足，兩者對應的改善方向不同。

## 16. Review Trigger

下列條件發生時，需求不會自動失效，但必須進入 Review Backlog：

- 連續 5 個工作日忽略率（含主動忽略與逾時未回應）明顯高於完成率。
- 使用者頻繁使用暫停或結束程式逃避提醒。
- 全螢幕或特定應用的誤判明顯。
- 背景 CPU、記憶體或電池消耗超標。
- 使用者表示提醒仍會搶焦點或遮擋內容。
- 產品原則與價值目標出現衝突。
- Windows API 或平台行為變更。
- 收到隱私、安全或法規風險回報。
- MVP Dogfooding 滿 10 個工作日。
- **被動休息判定與離席判定的預設值（20 秒／2 分鐘）在實測中出現大量誤判（例如使用者短暫離開又立刻回來卻被算作完成休息）。**

### 權限原則

- 任何 Agent 或團隊成員均可提出 Review（挑戰權不分層）。
- 可調參數可由工程與產品根據數據直接調整。
- 版本承諾須在 Sprint Planning 或 Review 中修改。
- 產品原則須由產品、工程與使用者代表共同審查。
- 安全、隱私、資料損失問題可立即中止當期開發或發布。

# 19. Agent 執行規則

其他 Agent 開工時應遵守：

1. 不得自行加入 Out of Scope 功能。
2. 技術細節可調整，但不得違反產品原則。
3. 若發現需求矛盾，建立 Decision Record，不得默默自行解釋（本次 v1.0 → v1.1 的修正即為此原則的實踐範例，見第 0 節）。
4. 所有可調數值必須配置化。
5. 核心時間邏輯必須使用 Fake Clock 測試。
6. UI 不得包含任何強制阻擋操作。
7. 不得記錄 Window Title、鍵盤內容或畫面內容。
8. 每完成一個 Backlog Item，必須附：
   - 變更摘要
   - 測試結果
   - 已知限制
   - 是否影響需求或資料結構
9. 若要修改產品原則或 MVP Scope，必須提出：
   - 問題證據
   - 影響範圍
   - 替代方案
   - 不修改的成本
10. 安全、隱私、資料損失問題可立即中止開發並要求 Review。

# 20. Definition of Done

每個 Backlog Item 完成時必須符合：

- 程式碼已完成。
- 單元測試或整合測試已新增。
- 所有既有測試通過。
- 無新增編譯警告。
- 已處理錯誤與降級情境。
- 日誌不包含敏感資訊。
- UI 符合不搶焦點與無障礙要求。
- 文件同步更新。
- 已知限制已明確記錄。
- 可由另一名 Agent 根據驗收條件重現結果。
